# Simplified WinUI Skill Agent Workflow

## Overview
This document describes the simplified workflow for the `winui-skill-agent` Ollama model and supporting infrastructure for Windows UI automation through AI.

## Workflow Architecture

### 1. User Initiates Request
User starts an Ollama session:
```bash
ollama run winui-skill-agent
```

User enters a request:
```
compute 45*67
```

### 2. Agent Loads Resources
The agent checks available resources:

**Step 2a: Load Skill Files**
- Primary skill: `Samples\Calculator.winui-skill.json` or `Samples\CalculatorButtonLibrary.winui-skill.json`
- Contains recorded UI automation tasks with node paths
- Provides launch, navigation, result verification, and cleanup tasks

**Step 2b: Load Skill Instructions**
When `--skills-folder` is provided, Ollama can load relevant `.md` files from `Samples\AgentSkills\`:
- `CalculatorExpression.skill.md` - Expression parsing and button transformation
- `WinUiSkillEditor.skill.md` - Skill adaptation and editing
- `WinUiSkillExecutor.skill.md` - Execution safety procedures

### 3. Agent Derives Skill JSON
The agent uses LLM reasoning to:

1. **Parse the expression**: Extract digits, operators, functions from user input
2. **Build task sequence**: 
   - Preserve launch and navigation tasks from source skill
   - Create one `leftClick` task per digit/operator
   - Add `Equals` button click at end
   - Preserve result verification and cleanup tasks
3. **Compose complete skill**: Generate full `.winui-skill.json` with all node paths

**Example for `45*67`:**
- Task sequence: `num4Button` → `num5Button` → `multiplyButton` → `num6Button` → `num7Button` → `equalButton`
- All node paths come from source skill's recorded locations
- Parent paths (like `StandardOperators` for operators) are preserved from source

### 4. Agent Validates with Dry Run
1. **Inspect desktop**: Call `get_snapshot` or `query_snapshot` to see current state
2. **Dry-run execution**: Call `run_skill` with `playbackOptions.dryRun: true`
3. **Review results**: Check each task completed successfully
4. **Request approval**: Show user the planned real actions and ask `RUN` or `CLOSE`

### 5. Execute (After User Approval)
1. **Real execution**: Call `run_skill` with `playbackOptions.dryRun: false`
2. **Verify result**: Call `locate` or `query_snapshot` to confirm Calculator shows correct answer
3. **Request cleanup**: Ask for approval before closing Calculator
4. **Cleanup**: Send close command and verify completion

## Key Files and Responsibilities

### Modelfile: `OllamaWinUiSkillAgent.Modelfile`
- Defines Ollama model configuration
- Sets temperature=0, num_ctx=32768, num_predict=-1
- Contains system prompt with procedural instructions
- Points to supporting skill instruction files

### Skill Instructions (in `AgentSkills/` folder)

#### `CalculatorExpression.skill.md`
- **Purpose**: Guide expression parsing and button mapping
- **Input**: User expression like `45*67`, `sqrt(16)`, `ln(2.718)`
- **Process**: 
  - Parse operators, functions, parentheses
  - Map to button IDs: `num0-9Button`, `plusButton`, `minusButton`, `multiplyButton`, `divideButton`, etc.
  - Support scientific functions with recorded button IDs
- **Output**: Ordered button sequence for Calculator

#### `WinUiSkillEditor.skill.md`
- **Purpose**: Guide skill JSON modification
- **Process**:
  1. Load source skill JSON
  2. Deep-copy to preserve original
  3. Identify variable input range (arithmetic tasks)
  4. Update only that range with new button paths
  5. Preserve launch, navigation, cleanup, and result tasks
  6. Validate JSON output
- **Safety**: Never overwrite source file; always save with new name

#### `WinUiSkillExecutor.skill.md`
- **Purpose**: Guide safe execution with approval gates
- **Process**:
  1. Desktop inspection
  2. Dry-run validation
  3. Explicit approval request
  4. Real execution
  5. Result verification
  6. Cleanup with approval
- **Safety**: Stop at first failure; report full error details

### Skill JSON Files

#### `CalculatorButtonLibrary.winui-skill.json` (Primary Source)
- Recorded button library with hover tasks for all Calculator buttons
- Provides node paths for:
  - Number pad: `num0Button` through `num9Button`, `decimalButton`
  - Standard operators: `plusButton`, `minusButton`, `multiplyButton`, `divideButton`
  - Scientific operators: `squareRootButton`, `powerButton`, `logBaseEButton`, etc.
  - Utility buttons: `equalButton`, `clearButton`
- Preserves launch, navigation, and result verification tasks

#### `Calculator.winui-skill.json` (Legacy Example)
- Specific recorded example: calculates `1 + 2 = 3`
- Used as template for adaptation
- Shows complete task structure

#### Derived Skills (Generated)
- `Calculator-45x67.winui-skill.json` (example output)
- Generated by agent for specific expressions
- Contains only needed button clicks, not full library

## MCP Integration

### MCP Server: `WinUiAutomation.McpServer`
Implements these tools:

| Tool | Purpose |
|------|---------|
| `run_skill` | Execute a skill JSON with optional dry-run |
| `get_snapshot` | Capture current desktop state |
| `query_snapshot` | Search desktop for element by properties |
| `locate` | Find element on desktop by node path |
| `load_source_skill` | Load full skill JSON for context |
| `perform_action` | Direct UI action (alternative to skills) |
| `get_screenshot` | Capture visual screen state |

### MCP Host Options

#### Option 1: `OllamaMcpHost` (Recommended - No Python)
- C#/.NET bridge between Ollama and MCP
- Starts MCP server as child process
- Catalogs and loads skill instructions on demand
- Requires `--skills-folder` to enable instruction loading

**Usage:**
```bash
dotnet run --project .\Samples\OllamaMcpHost\OllamaMcpHost.csproj -c Release --no-build -- \
  --model winui-skill-agent:latest \
  --skill .\Samples\CalculatorButtonLibrary.winui-skill.json \
  --skills-folder .\Samples\AgentSkills
```

#### Option 2: Python Bridge (Reference Only)
- `OllamaCalculatorWorkflow.py`
- Connects Ollama HTTP API to MCP stdio
- Useful for scripting and reference
- Requires Python environment

## Supported Expressions

### Basic Arithmetic
- `45+67`, `100-33`, `12*34`, `48/8`
- Decimal points: `3.14*2`
- Parentheses: `(10+5)*2`

### Scientific Functions
- Powers: `2**8`, `10**3`
- Roots: `sqrt(16)`, `sqrt(144)`
- Logarithms: `ln(2.718)`, `log(100)`
- Trigonometry: `sin(90)`, `cos(0)` (via Calculator's Scientific mode)
- Modulo: `17 mod 5`
- Reciprocal: `1/4`
- Absolute: `abs(-5)`
- Scientific notation: `exp(2,3)` for `2×10³`

## Safety Procedures

1. **Always dry-run first**: No real input until `playbackOptions.dryRun: true` completes successfully
2. **Request explicit approval**: Show user planned actions before proceeding
3. **Validate results**: Query desktop state to confirm expected outcome
4. **Handle failures gracefully**: Stop at first error and report full context
5. **Never invent paths**: Use only recorded node paths from source skills
6. **Preserve structure**: Keep launch, navigation, and cleanup tasks intact

## Configuration Examples

### Basic Setup (Deterministic Calculator)
No `--skills-folder`: basic arithmetic only via deterministic host-side parsing.

```bash
dotnet run --project .\Samples\OllamaMcpHost\OllamaMcpHost.csproj -c Release --no-build -- \
  --model winui-skill-agent:latest \
  --skill .\Samples\Calculator.winui-skill.json
```

Then: `compute 45+67`

### Advanced Setup (Ollama-Driven with Instructions)

Then: 
- `compute 45*67` (arithmetic)
- `compute sqrt(144)` (scientific)

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Expression parsing fails | Load `CalculatorExpression.skill.md` for guidance |
| Button not found | Ensure source skill has recorded button library or current expression doesn't require unsupported functions |
| Dry-run fails | Check source skill JSON is valid; re-run with original skill to confirm baseline works |
| Approval prompt doesn't appear | Ensure host config requires approval for `dryRun: false` execution |
| Result verification fails | Use `query_snapshot` to check actual display; may differ from expected |
| Cleanup fails | Leave Calculator open rather than failing; don't invent close targets |
